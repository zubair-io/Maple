# Full-Fidelity "(mixed)" Detection Across All Batch-Metadata Fields

**Goal:** Provide the web Batch Metadata panel with the full per-asset metadata snapshot (all ~22 editable fields) so "(mixed)" detection is accurate across every field, not just the ~6 fields carried by the thin browse-shell asset view-model.

**Architecture:** A new `POST /api/metadata/snapshots` route accepts a list of absolute asset paths and returns the effective metadata (from `metadata_override` in the DB, falling back to EXIF) for each path in the same `XmpMetadata`-shaped flat object the panel already expects. The browse-shell calls this endpoint when opening the panel (replacing the thin inline snapshot construction), passes the enriched snapshots to the panel component unchanged, and the existing `computeMixedValues` pure function handles "(mixed)" detection for all 22 fields without any change to the panel or its types.

**Tech Stack:** Bun + Elysia (API route), MongoDB (assets collection), Angular HttpClient + RxJS (web service call from browse-shell component), Vitest + Angular TestBed (web specs), bun:test + Elysia test app (API specs).

## Background: how the current thin snapshot is built

`BrowseShellComponent.onEditMetadata()` (`src/web/projects/maple-common/src/lib/shells/browse-shell/browse-shell.component.ts`, lines 149–165) builds `AssetMetadataSnapshot[]` inline from the in-memory asset list. The asset view-model carries only the fields the grid displays: `gps.lat/lon`, `city`, `country`, `title`, `keywords`. The other 16 editable fields (`caption`, `headline`, `creator`, `creatorJobTitle`, `state`, `sublocation`, `countryCode`, `timeZone`, `dateTimeOriginal`, `instructions`, `copyrightNotice`, `usageTerms`, `credit`, `source`, `copyrightStatus`, `gpsAltitude`) are always `undefined` in the snapshot, so `computeMixedValues` never sees them as "(mixed)" even when they differ across the selection.

## Where the data lives

The API database stores user edits as `metadata_override` on the asset document (see `src/api/src/db/schema.ts`, `MetadataOverride` interface, ~line 1227). The existing effective-resolver (`src/api/src/metadata/override-resolver.ts`) computes the fields the effective-metadata service needs, but covers only a search/sort subset (`captured_at`, `gps`, `time_zone`, `place_text`). The full flat set of all 22 panel fields lives directly on `metadata_override` — the remaining fields map as follows:

## API design: `POST /api/metadata/snapshots`

**Request body:**
```json
{ "paths": ["/abs/path/a.dng", "/abs/path/b.dng"] }
```

**Response body (200):**
```json
{
  "snapshots": [
    {
      "path": "/abs/path/a.dng",
      "metadata": {
        "gpsLatitude": 48.8566,
        "gpsLongitude": 2.3522,
        "city": "Paris",
        "caption": "Tower at dusk",
        "copyrightStatus": "copyrighted"
      }
    },
    {
      "path": "/abs/path/b.dng",
      "metadata": {}
    }
  ]
}
```

- `paths` may contain up to 1000 entries (same ceiling as `/api/xmp/batch`).
- Each `metadata` object carries **only the fields that have a non-null effective value** — absent keys signal "not set", which `computeMixedValues` already treats as `undefined`.
- Paths that fail authorization or are not found in the DB return `{ "path": "...", "metadata": {} }` — safe (unknown ≡ no value).
- The route is auth-gated the same way as the rest of `batchMetadataRoutes` (same Elysia plugin, same authed subtree).

## DB lookup strategy

The route receives absolute paths. To look up assets, the same filename-based query pattern as `backup-refile.ts` (`findGeoBackupDocs`) applies: query by `{ 'fileinfo.filename': { $in: filenames } }`, then post-filter by reconstructing each doc's abs path from the library map and intersecting with the request set. This avoids a full table scan.

Projection: `{ metadata_override: 1, exif: 1, fileinfo: 1 }`.

After filtering to the exact request paths, translate each doc's `metadata_override` + `exif` into the flat `XmpMetadata`-shaped object using a pure `overrideToXmpSnapshot(doc)` helper — no Angular, no side effects, testable in isolation.

## Helper: `overrideToXmpSnapshot`

```typescript
function overrideToXmpSnapshot(
  doc: Pick<AssetDoc, 'exif' | 'metadata_override'>,
): Partial<XmpMetadata> & { keywords?: string[] }
```

Returns only the fields that have a non-nullish effective value (override ?? exif ?? skip). For fields that don't have an exif equivalent (caption, headline, creator, etc.) the formula is just `override.field ?? undefined`. This keeps the response payload compact and matches the existing `AssetMetadataSnapshot.metadata` shape.

## Angular service change

`BatchMetadataService.fetchSnapshots(paths: string[]): Observable<AssetMetadataSnapshot[]>` — `POST /api/metadata/snapshots`, maps the response to `AssetMetadataSnapshot[]`.

## Browse-shell change

`onEditMetadata()` builds the path list, then calls `fetchSnapshots(paths)` (subscribes once, no leak — the subscription is for a single panel-open event). On success it sets `batchMetaAssetSnapshots` and opens the panel. On error it falls back to the thin snapshot (same fields as today) so the panel still opens — degraded "(mixed)" detection, not a blank panel.

The browse-shell holds a `Subscription | null` for in-flight snapshot fetches and cancels it in `onBatchMetaDismiss` if the user somehow dismisses before the fetch resolves.
