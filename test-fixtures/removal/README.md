# Removal persistence interoperability corpus

Small synthetic fixtures for the durable object-removal edit format. The
Rust, Swift, C# and browser WASM tests that land with the later #4495 slices
read these same bytes, so companion publication, sidecar saves and
saved-session rendering are checked against one contract instead of
per-platform regenerated inputs. On `main` today the only reader is the
copy check below. Nothing here is a photograph: `source.dng` is a 16×8
synthetic grey DNG.

## `basic/`

- `source.dng` — 16×8 synthetic grey DNG (774 B).
- `mask.mimf` — lossless removal mask covering the 8×4 window at (4, 2).
- `patch.f16` — HDR scene-linear patch for that window. Values include a
  negative channel and a channel above one; preserving them is part of the
  contract.
- `request.txt` — the preparation request, as the exact compact JSON wire text
  produced by Rust (canonical attribute ordering, no reformatting).
- `records.txt` — the accepted records produced from that request, same wire
  form. The blake3 digests inside name the committed `mask.mimf` and
  `patch.f16` bytes.
- `prior.xmp` — a foreign XMP envelope that a save must carry through
  untouched.

## `calibration/`

The same RAW and signed HDR patch bound to the real decoder's fixed
linear-calibration source anchor (schema 4). `saved.xmp` references both
companions. `preview-4.*` and `preview-64.*` are RGB8 Auto-quality display
renders of the saved stack at 4 px and 64 px long-edge requests, taken from the
shared display chain before any host image conversion: `.rgb` is the raw pixel
buffer, `.json` its dimensions, and `-q90.jpg` a quality-90 JPEG encoded from
those same committed pixels, usable as an independent lossy-derivative oracle.

## Apple copy

SwiftPM test resources cannot reach outside the package, so a byte-identical
copy lives under `src/apple/Packages/MapleCore/Tests/MapleCoreTests/Fixtures/removal/`:
`basic/*` sits at that directory's root and `calibration/` keeps its own
directory. Commit both copies together; `tools/check_removal_fixture_copies.py`
fails when they drift.

```sh
python3 tools/test_removal_fixture_copies.py
python3 tools/check_removal_fixture_copies.py
```

## Provenance

Generated by the raw-core example `removal-fixture` on the
`codex/ai-object-removal` branch (branch tip `44d342ac`; `test-fixtures/removal`
was last written at `0d4b80c795` and the Apple mirror at `c764881471`). The generator depends on the removal core
(`prepare_accepted_removal`, `removal_mask_to_bytes`,
`types::accepted_removal`, `types::removal_mask`,
`ResolvedCalibrationRemovals`), which lands with slice S8 of the #4495 plan;
until then these bytes are the contract and are not regenerable from `main`.
Once S8 lands, regenerate from the repository root with:

```sh
cargo run --manifest-path src/raw-pipeline/Cargo.toml -p raw-core --features test-support --example removal-fixture -- test-fixtures/removal/basic
cargo run --manifest-path src/raw-pipeline/Cargo.toml -p raw-core --features test-support --example removal-fixture -- test-fixtures/removal/calibration --calibration
cp test-fixtures/removal/basic/* src/apple/Packages/MapleCore/Tests/MapleCoreTests/Fixtures/removal/
cp test-fixtures/removal/calibration/* src/apple/Packages/MapleCore/Tests/MapleCoreTests/Fixtures/removal/calibration/
```

Both copies are marked `-text` in `.gitattributes` and the Apple mirror is
listed in `.prettierignore`: the records are
digest-bound, so a line-ending normalisation on any platform would silently
break them.
