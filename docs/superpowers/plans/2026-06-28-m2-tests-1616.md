# Plan: rewrite M2 batch-metadata specs to test the real code (#1616)

The three batch-metadata spec files under
`src/web/projects/maple-common/src/lib/batch-metadata/` exercise the right
behaviours but do so by re-declaring private helpers instead of importing and
invoking the real component and service. This plan describes exactly what
changes and why.

## Problem in each file

**`batch-metadata-panel.component.spec.ts`** skips Angular TestBed entirely.
It avoids the real `BatchMetadataPanelComponent` by copy-pasting four
functions from its private internals: `geocodeSelectToFields`, `parseKeywords`,
`buildPayload`, `gpsWasTouched`/`refileOfferDecision`. If a bug is introduced
in `onGeocodeSelect`, `_buildPayload`, or `onConfirm`, the tests still pass
because they never call those methods — they only exercise the local copies.

**`batch-metadata.service.spec.ts`** imports the real `computeMixedValues`
pure function (good), but the HTTP layer is declared "covered by type
contracts." The "RefileCountResult type contract" and "RefileResult type
contract" describe-blocks do nothing more than assign TypeScript literals and
assert their own properties — they carry zero confidence that the service
methods make the right HTTP calls. The `BatchMetadataService` itself is never
instantiated.

**`batch-metadata.service.http.spec.ts`** is already correct: it uses Angular
TestBed, `HttpTestingController`, and the real `BatchMetadataService`. It only
lacks coverage for `batchApply` and `geocodeSearch`.

## What the rewrite does

### `batch-metadata-panel.component.spec.ts` — full rewrite

Replace all local helper copies with Angular TestBed tests that instantiate
the real `BatchMetadataPanelComponent`. Strategy:

- Use a thin `HostComponent` wrapper (same pattern as `bottom-sheet.component.spec.ts`)
  that passes `visible` and `assetSnapshots` via inputs and captures `dismiss` events.
- Provide `BatchMetadataService` via `HttpTestingController` so the component's
  `batchApply`/`refileCount`/`geocodeSearch`/`refile` calls can be flushed inline.
- Keep all the same behavioural assertions from the original spec, but now driven
  through the real component: field-change fires `onFieldChange`, `onGeocodeSelect`
  sets the six coordinate/place signals, `_buildPayload` is called inside `onConfirm`.
- The pure-function `computeMixedValues` tests stay via direct import (they were
  already correct in this regard); `batch-metadata.service.spec.ts` retains them.
- Refile-offer phase tests call `onConfirm()` on the component and flush
  the `batchApply` + `refileCount` HTTP calls to exercise the real branching logic.
- Geocode pipeline tests call `onGeocodeQueryInput()` and flush the geocodeSearch
  response to confirm `catchError`-inside-`switchMap` yields `[]` on failure.

### `batch-metadata.service.spec.ts` — tighten

Remove the type-contract `describe`-blocks (they add no confidence). Those
types are already compile-checked. Consolidate the `computeMixedValues` tests
(which are valid) into this file unchanged. Optionally merge into the http spec,
but keeping a separate file is fine since the pure-function tests run under
bare vitest while the HTTP suite needs ng test.

### `batch-metadata.service.http.spec.ts` — extend

Add two new test cases:

- `batchApply` POSTs to `/api/xmp/batch` with `{ entries }` body.
- `geocodeSearch` GETs `/api/geocode/search?q=<query>` and extracts
  `suggestions` from the response envelope.

## Test inventory after the rewrite

The real component/service is exercised for every behaviour that was previously
behind a local copy:

| Behaviour                               | How tested after rewrite                                                  |
| --------------------------------------- | ------------------------------------------------------------------------- |
| mixed-value detection                   | `computeMixedValues` direct import (kept)                                 |
| only-touched-fields payload             | `onFieldChange` + `onConfirm` → flush `batchApply`, assert request body   |
| explicit-clear vs untouched             | same path: empty string → `null` in request body                          |
| geocode `catchError`-inside-`switchMap` | `onGeocodeQueryInput` → flush with HTTP error → assert candidates = []    |
| `onGeocodeSelect` unconditional-set     | call `onGeocodeSelect` on real component → assert all six signals         |
| refile-offer show vs auto-dismiss       | `onConfirm` → flush `batchApply` 200 → flush `refileCount` → assert phase |
| refile-count fail → auto-dismiss        | `onConfirm` → flush `batchApply` 200 → flush `refileCount` with error     |
| HTTP wiring (`batchApply`)              | `HttpTestingController` in service http spec                              |
| HTTP wiring (`geocodeSearch`)           | `HttpTestingController` in service http spec                              |
| HTTP wiring (`refileCount`, `refile`)   | already covered, kept                                                     |
