# Apple Batch Metadata Parity — ticket #1633

Milestone M4 (#1632) shipped the Apple Batch Metadata sheet but left two fields
absent that the web M2 panel has: a manual altitude input and a keywords editor.
This plan closes those gaps.

## What already exists

`BatchMetadataViewModel.TouchedMetadata` already declares `gpsAltitude:
Optional<Optional<Double>>` and the XMP layer (`XMPSerialization+Metadata.swift`,
`XMPSerialization+MetadataWrite.swift`) already serialises and parses it.
The "Clear GPS" button in `BatchMetadataCaptureSection` already writes
`.some(nil)` into `touchedMetadata.gpsAltitude`. What is missing is a
text field that lets the user enter or edit an altitude value without a
geocode search, and that feeds `touchedMetadata.gpsAltitude = .some(meters)`.

Keywords (`dc:subject`) round-trip through `CullingState.keywords` — the XMP
layer serialises them as an `rdf:Bag` under `dc:subject` and the parser reads
them back. `XMPSidecarStore.update(model:culling:metadata:)` already persists
both. What is missing is a `[String]??` slot in `TouchedMetadata` for keywords,
mixed-value detection for them in `detectMixed`, an `applyTouched` branch that
writes them into the merged culling state, and a text field in the UI that
renders and edits them as a comma-separated string (matching the web panel).

## Changes

### `BatchMetadataViewModel.swift`

`TouchedMetadata` gains `keywords: Optional<Optional<[String]>>`. The triple
optionality mirrors the GPS fields: outer nil means untouched, `.some(nil)` or
`.some([])` means explicit clear (empty list), and `.some([...])` means replace.

`MetadataFieldKey` gains a `.keywords` case.

`applyTouched(_:into:)` is extended. For keywords the merge target is the
`culling` argument in `applyToAsset`, not `XmpMetadata`, so `applyTouched`
does not operate on `XmpMetadata` directly — instead `applyToAsset` reads
`touchedMetadata.keywords` and merges it into `culling` before calling
`store.update(model:culling:metadata:)`. The video path (metadata-only sidecar)
stores keywords in the XMP sidecar by building a temporary culling-only sidecar
structure; since video sidecars currently don't support keywords in M5 scope,
keywords apply is a no-op for video assets (consistent with the spec saying M5
handles video metadata depth).

`detectMixed` gains a `checkKeywords()` helper that compares `[String]` arrays
across loaded culling states. Because `readMetadata(for:)` already reads the
sidecar XML, keywords are parsed alongside it by calling `XMPParser.parse` to
also get the `CullingState` for each asset. A lightweight second parse for
keywords is acceptable here (the sidecar is already in memory as a String).

`hasTouched` is updated to include `keywords`.

`loadExistingMetadata` reads both XmpMetadata and CullingState.keywords per
asset; the detectMixed helper receives a parallel `cullings: [CullingState]`
array.

### `BatchMetadataCaptureSection.swift`

An "Altitude (m)" text field is added below Latitude/Longitude, parallel to
the web input. It uses a `@State private var altText: String` buffer and
writes `touchedMetadata.gpsAltitude = .some(Double(v))` on change, or sets
it to `nil` (untouched) when the field is emptied by the user. The placeholder
shows the common altitude (formatted to 1 decimal place) or "(mixed)". The
existing Clear GPS button already writes `.some(nil)` into `gpsAltitude` and
clears `altText`.

`applyPlacemark` is extended to read `loc.altitude` when available (non-zero
— CoreLocation returns 0 when elevation data is absent). When the placemark's
altitude is non-zero the function sets `touchedMetadata.gpsAltitude = loc.altitude`
and updates `altText`.

### `BatchMetadataTextSection.swift`

A "Keywords" field is added at the bottom of the Description group (between
Instructions and the next group), matching the web panel's position. It shows
a single `TextField` accepting a comma-separated string. On commit or change
it parses the string by splitting on commas (and trimming whitespace), dedupes,
drops blanks, and writes into `touchedMetadata.keywords`. An empty field maps
to explicit clear (`.some([])`); a field that was never edited leaves it nil.
Mixed-value display shows "(mixed)" in the placeholder.

### `BatchMetadataViewModelTests.swift`

Two new tests are added:

- `testApplyAltitudeToAltitude` — creates an asset with no altitude, applies
  `gpsAltitude = 1234.5` via the VM, reads back the sidecar, confirms
  `gpsAltitude ≈ 1234.5` (within 0.001 m).
- `testApplyKeywordsRoundTrip` — creates an asset with existing keywords
  `["travel"]`, applies `keywords = ["france", "street"]` via the VM, reads
  back the sidecar (both XMPParser.parse to get culling.keywords), confirms
  the new set is `["france", "street"]` and that an unrelated metadata field
  (e.g. city) is unaffected.

## What is not in scope

The video path for keywords (requires M5 video metadata depth — tracked in
#1638). Altitude editing in the geocode-result picker (Apple does not expose
elevation in CLPlacemark reliably when elevation data is absent). A chip/tag
UI for keywords (the web panel uses a plain text input; parity is the target
for this ticket).
