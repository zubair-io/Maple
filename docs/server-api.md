# HTTP Route Reference

Every HTTP endpoint the Maple server exposes, grouped by area. Routes are defined in `src/api/src/routes/` (plus `src/api/src/workers/routes-main.ts` and `workers/generated-search/routes.ts`) as Elysia plugins, each carrying a prefix; `src/api/src/index.ts` mounts them, and `src/api/src/routes/authed-api.ts` is the wrapped sub-app that applies one shared `requireAuth` to the bulk of them. Handler mechanics, the auth model, and the settings system are in [api](api.md).

The server also serves an OpenAPI description of itself: Scalar UI at `/docs`, spec JSON at `/openapi.json`, both unauthenticated so clients can codegen DTOs from them.

## Auth legend

| Marker      | Meaning                                                                                       |
| ----------- | --------------------------------------------------------------------------------------------- |
| public      | No credential required                                                                        |
| bearer      | Valid access token in `Authorization: Bearer`                                                 |
| +file       | Bearer plus the per-user `file_access` permission                                             |
| owner       | Bearer plus `role: owner`                                                                     |
| +step-up    | Additionally requires a fresh `X-Step-Up` token from `POST /api/auth/step-up/verify`          |
| ?token      | Access token in the `token` query parameter (media elements and WebSockets can't set headers) |
| service key | A `maple_sk_…` service API key, not a user token                                              |

Anything marked bearer or stricter returns the standard error envelope on failure: `{ error, code, requestId, details? }`.

**What `file_access` covers (#2893, #4746).** It gates everything that reads or changes the library as files: raw-file reads by path, absolute server paths, browsing, and moving, renaming, relocating or trashing files on disk. A member without it keeps photo backup, timeline, search and editing. Sidecar writes (`/api/xmp`, `/api/assets/:id/xmp`, XMP variants), rendered-preview publishing (`PUT /api/preview`) and backup ingest are editing and backup flows, so they stay at plain bearer on purpose.

| GET    | `/api/mirror/orphans`             | owner  | Dry-run report of mirror files with no primary counterpart. Deletes nothing                                                                                  |

A `.xmp` uploaded through `/api/folders/:id/upload` never replaces a sidecar: when the name is already taken, including by a save through `PUT /api/assets/:id/xmp` or `POST /api/libraries/:libraryId/backup/sidecar` that lands while the upload is in flight, the route answers 409 and the existing sidecar is kept. Edit sidecars through the XMP routes.

Known limitation (#5143): on volumes that refuse hard links (SMB/CIFS), the upload checks that the name is free and then renames the complete file into place, both inside the sidecar save barrier. Every writer inside Maple takes that barrier, but a writer outside it — the native app or another tool writing to the share directly — can create the sidecar in the moment between the check and the rename, and its edit is then replaced. Closing this needs a rename that refuses to replace an existing file (`renamex_np` with `RENAME_EXCL`, `renameat2` with `RENAME_NOREPLACE`), which smbfs and CIFS, the only volumes this path serves, generally don't support.

Media uploaded through `/api/folders/:id/upload` is attributed to the authenticated uploader, including when the filesystem watcher creates the asset first. Client-supplied owner headers are ignored. Internal writers without a principal preserve existing attribution; a principal whose user row is absent leaves new assets unassigned and keeps an existing asset's owner.

## Unified addressing (`slug:relPath`)

The four routes clients should prefer. Each resolves the slug through an in-memory cache and jails the relative path with a realpath check.

| Method | Path                   | Auth   | Purpose                                                                                                                                                                                                                                                                                                                          |
| ------ | ---------------------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/folder/:slug`    | +file  | Library-root listing. Registered separately because Elysia's `*` doesn't match an empty tail                                                                                                                                                                                                                                     |
| GET    | `/api/folder/:slug/*`  | +file  | Enriched folder listing: indexed catalog entries plus on-disk media, subfolders, sidecars and ordinary files; optional cursor paging and body ETag                                                                                                                                                                               |
| GET    | `/api/image/:slug/*`   | bearer | Stream original bytes from the primary or a faithful mirror; fail over when the primary root is unavailable. Single byte ranges return 206 or 416; Content-Type comes from the extension                                                                                                                                         |
| GET    | `/api/thumb/:slug/*`   | bearer | Thumbnail AVIF with a body-hash ETag and private revalidating caching. Validates original/XMP freshness before a conditional 304; generates on a cache miss even before indexing. Cold reads return actionable 503 errors when the native decoder or video ffmpeg is unavailable. This is the route the Cloudflare Worker fronts |
| GET    | `/api/preview/:slug/*` | bearer | 1280 px preview AVIF for indexed assets, generated on a cold miss. Preview mtime/size ETag and private revalidating caching; original/XMP freshness is checked before 304. Unindexed assets return retryable 202; missing cold decoders return actionable 503                                                                    |
| GET    | `/api/video/:slug/*`   | ?token | Ranged video streaming                                                                                                                                                                                                                                                                                                           |
| GET    | `/api/video/fs`        | ?token | Ranged video streaming by absolute path                                                                                                                                                                                                                                                                                          |

Both folder route forms preserve the Web `address`, `parent` (parent address), `folders` and `images` fields. They also return `path` and `parentPath` (absolute server paths; null parent at the library root), `files` and `sidecars`. Every entry has its own `address`, logical library `path` (preserving symlink/root spelling), `size, `mtime`(ISO-8601) and lowercase`ext`. Images retain `mapleId`/`indexed`/dimensions/capture date and add indexed `id`and`exif`, plus `isVideo`/`isStub`/`isAudio`where applicable. Present files use actual filesystem metadata; absent catalog entries retain their indexed size and mtime. Sidecars carry their paired`asset_id`, including canonical/conflict XMP and the video's full-filename XMP convention. Orphan XMPs are omitted.

The listing and each folder entry additionally return `realPath` (the canonical server directory path; the listing uses null when unavailable). Logical `path` remains the navigation and addressing contract. Recursive move pickers use physical identity to stop symbolic-link cycles and exclude aliases into the moving subtree; they fail visibly on servers that lack this field rather than offering an incomplete or unsafe tree.

`?limit=N&cursor=<opaque>` pages the sorted directory-wide union across all entry types. No paging parameters returns the complete listing. Limits clamp to 1–2000 (default 500 in paged mode); malformed limits/cursors return 400. `next_cursor` is absent on the final page. Sidecar pairing consults the directory catalog, so a sidecar keeps its asset identity when the photo appeared on another page. Dot/cache/marker entries, soft-deleted assets and child symlinks escaping this specific library are excluded. Unindexed media enqueue durable discover work; hashing remains with the paced worker.

The response emits a body-hash ETag and `Cache-Control: private, max-age=0, must-revalidate`; matching `If-None-Match` returns 304. Each page's ETag covers its filesystem and indexed metadata. Apple native directory DTOs decode `parentPath` as the absolute parent and `folders` as directory children. File Provider forwards cursor/limit and revalidates each complete page URL independently.

## Sidecars, previews, and metadata

| Method | Path                      | Auth   | Purpose                                                                                                                                                                                                   |
| ------ | ------------------------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/xmp`                | bearer | Read the sidecar with a content ETag for `?path=`. Path-keyed, not id-keyed, so two paths sharing a `maple_id` keep two distinct sidecars                                                                 |
| POST   | `/api/xmp`                | bearer | Write it. Body is the full XMP document; optional strong `If-Match` or create-only `If-None-Match: *` rejects stale writes with 412                                                                       |
| DELETE | `/api/xmp`                | bearer | Delete it                                                                                                                                                                                                 |
| POST   | `/api/xmp/batch`          | bearer | Merge metadata fields into N sidecars addressed by `slug:relPath`, then mark each asset's `sidecar-metadata-index` stage dirty. Per-entry failure reporting; successes are not rolled back                |
| POST   | `/api/metadata/snapshots` | bearer | Effective metadata for a batch of paths, merging `metadata_override` over `exif`. Only non-null fields appear, so the Batch Metadata panel can detect mixed state                                         |
| PUT    | `/api/preview`            | bearer | Publish an already-rendered preview for `?path=` into `.maple/previews/`. Accepts AVIF or JPEG (sniffed by Content-Type then magic bytes) and transcodes JPEG to AVIF; the write is temp-file-then-rename |

Path-keyed XMP reads (including absent-sidecar 404s) advertise
`X-Maple-Xmp-Preconditions: content-etag-v1`. Successful reads and conditional
saves return the exact published body's strong `ETag`. Conditional checks share
the server's sidecar write barrier; concurrent clients with one baseline cannot
both replace it. Create-only publication also uses an atomic filesystem link; on volumes without hard links (SMB, exFAT) it renames the staged file into place after an absence check under the same barrier, so only a writer outside Maple can race it (#5151).
Malformed, weak or combined precondition headers return 400. A 412 leaves the
canonical sidecar unchanged; the client retains its pending edits and offers
reload/conflict handling. Older callers without preconditions retain their
existing unconditional write behaviour. `/api/xmp/batch` reads, merges and
writes each sidecar inside the same barrier, so a save cannot land between its
read and its write. Each sidecar whose bytes actually changed records one
change-feed row, so File Provider clients refetch it; an entry that leaves the
sidecar identical is not rewritten and records none. The write barrier is in-memory, so these
checks coordinate only writers inside the API process. The worker child process
(for example batch-sync jobs) and external filesystem writers do not participate
and can still race a conditional save.

## Search

Every filter parameter below is shared by `/api/search`, `/api/search/facets`, `/api/search/buckets`, and `/api/map/clusters`, declared once in `routes/search/query-schema.ts`.

`owner=<24-character hex user id>` filters those endpoints and `/api/assets` by uploader. `ownerId` and `owner_id` remain accepted aliases; `owner` takes precedence when multiple aliases are supplied. Invalid IDs return 400. Search totals and Timeline bucket caches normalize all three aliases to the same owner key and keep different users isolated.

| Method | Path                                 | Auth        | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ------ | ------------------------------------ | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| GET    | `/api/search`                        | bearer      | Paginated results. Default capture-time sorts use seek pagination and answer with `cursorPaging: true` plus a `nextCursor`; every other sort, and the text path, stays on `page`/`limit` and says `cursorPaging: false`. For free text, `total` is a window size by contract, not a match count (#4514): clients label it open-ended ("100+", "5,000+") while `more` or `capped` is set. A free-text query is answered from its ranked window, whichever engine ranks it (the in-process child or the database's full-text index): the engine ranks the text, SQL filters its hits, and `total` is the window's size, never a count of every match, so a free-text `total` is never above 5,000. `more: true` says a deeper page widens the window; The window is filled to the quota of the ladder step that reaches the requested page (steps of 100, 400, 1,600 and 5,000 hits serving 75, 300, 1,200 and 3,750 rows; the last quarter is headroom for copies and filtered hits), widening ×4 while the filters thin it, so every page indexes rows earlier pages served in full. `capped: true` says it stopped at the 5,000-hit cap with matches left, so paging ends there. `placeQuery` longer than 1,000 characters is rejected with 400. `/api/search/facets` and `/api/search/buckets` count the same window for the same `page` and `limit`. Results within a window are in relevance order with ties broken by a stable index order rather than capture date, so a deeper page always extends a shallower one. A free-text window shows one tile per shot (#4557): copies of one photograph (same owner, media kind and capture second, same filename once the extension, `(n)` markers and an export suffix are removed) collapse to the best-ranked one, and `total`, `more`, `capped`, facets, buckets, map clusters and hybrid `POST /api/search/assets` count shots, not files. |
| GET    | `/api/search/facets`                 | bearer      | Facet buckets over the caller's current filter, so dropdowns show what's in scope rather than the global universe. A text query is faceted over its ranked window, the same window `/api/search` serves for the same `page` and `limit` from the same engine: `total` is the window's size (at most 5,000, never a count of every match) and `scope` is `{kind:'all'}`. Clients send the list's current `page` and `limit` so facets follow a widened window. Without text, every match is counted and `total` is exact                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| GET    | `/api/search/buckets`                | bearer      | Year/month histogram for the Timeline, off pre-computed `exif.captured_year`/`month` so the group is index-only. Cached 30s per filter set. A text query's histogram covers its ranked window for the request's `page` and `limit`, like the facets                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

| GET    | `/api/generated-searches/:id/assets` | bearer      | Return one collection's results by re-running its stored query live, which is what forces the hidden-people and screenshot exclusions onto queries written by older worker versions. A snapshot is not page 1 of a paginated sequence, so page from a live request. One ranking per free-text search (#4542): every free-text `GET /api/search` page answers with an opaque `rankPin` naming the engine and window steps it was ranked at, plus a fingerprint of the search. A client sends it back as `rankPin` with the next page (never with page 0, which is a 400, as is a pin the server could not have minted), and that page is ranked by the same engine over the same steps, so pages never mix engines or window depths. An index change between two pages can still move rows, as it always could. When that engine cannot answer, or the pin was minted for a different search, the page is a 409 with `code: 'rank_engine_changed'` and the client restarts from page 0 without a pin.

Common search filters: `q` (filename substring), `placeQuery` (full-text over place, description, and OCR), `libraryId`, `camera`, `lens`, `isoMin`/`isoMax`, `apertureMin`/`apertureMax`, `focalMin`/`focalMax`, `from`/`to`, `month` (recurring month-of-year), `rating`, `flag`, `color`, `ext`, `pathPrefix`, `hasCapturedAt`, `sceneType`, `activity`, `subjects` (comma-separated), `people` (comma-separated names), `place` (pipe-separated labels), `isScreenshot`, `scope` (`photos` | `places` | `people` | `albums`), plus `sort`, `page`, `limit`, `cursor`.

A completed ingest's retry sends every chunk again before success: a stored session or path can't prove the original bytes still live there. ### Re-sending a newer edit (`X-Maple-Sidecar-Base`)

A device that edits a photo after backing it up re-sends the sidecar, naming the version its edit was based on: the SHA-256 (hex) of the XMP it last delivered, or `none` for its first sidecar. The write never skips (#4719):

- nothing on disk yet → written;
- the server already holds exactly this XMP → `unchanged: true`, no write;
- the server still holds the named version → overwritten;
- anything else → the edit is written on top, `diverged: true`, and the displaced XMP is kept in the `sidecar_divergences` table with both digests, the device and the asset;
- except when another photo with the same stem shares that sidecar (`IMG.jpg` + `IMG.cr2` → `IMG.xmp`, #4692): then only the named version may be replaced. Any other edit leaves the sidecar as it is, returns `shared: true`, and is kept in `sidecar_divergences` instead (its displaced and incoming digests are equal, marking the incoming edit as the one set aside).

Before #5021 the route wrote `<target>.xmp` (`IMG.HEIC.xmp`), which the server never reads. A send that lands now counts as a server edit of the photo (`has_xmp`, `sidecar_ver`, a change-feed row, so cloud backup and File Provider pick it up) and retires that photo's old-name file, keeping its edit in `sidecar_divergences` when it differs; only files carrying Maple's XMP namespace are touched. The edit is recorded strictly inside the write barrier just before the bytes land; if that fails, nothing is written and the send fails, so the device retries. The device ignores revisions it recorded before #5021 (or that an un-upgraded server stored under the old name), so its next library walk sends each edit again, based on its last delivered digest.

The operator-enabled `canonical-backup-sidecars` migration on Settings → Workers handles the files no device re-sends. It runs in the worker child, outside the API process's in-memory barrier, so it never overwrites: it creates the canonical sidecar when none exists, and when one exists (a server edit) it leaves that active and keeps the old-name edit in `sidecar_divergences`. Edits from devices that no longer exist therefore end up kept aside rather than on top; a live device's re-send still lands its edit on top through the API. Nothing is deleted without being recorded. It skips a library whose volume is not mounted. Every mover (trash and restore, refile, duplicates, relocate and external-rename reconciliation) carries a photo's Maple old-name file with it, renamed to the photo's new full name, so the migration finds it at the photo's current path (#5063). Wherever Maple picks the name (refile, backup ingest, auto-suffix and restore), it treats a name with another photo's stranded old-name file (matched case-insensitively) as taken, because the migration would otherwise hand that edit to the new photo.

The check and the publish run under the shared sidecar write barrier, so two edits racing on one base serialise: one overwrites, the other diverges, and neither version is lost. If the publish itself fails, the divergence row is dropped again, so retries don't pile up copies.

Guards on both paths (with or without the header):

- the target path must be a live (not deleted, not missing) location of the resolved asset (a `404` otherwise), because the canonical sidecar it names is where that photo's edits are read from (#5021);
- the destination is checked against the library roots, resolving symlinked folders, before anything is read or any directory is created; a destination outside the library is a `400`, including one swapped in while the write waits on the barrier;
- a write that fails is a `500`, and nothing is recorded for it.

Guards with a base only:

- a malformed base is a `400`.

A request without the header keeps the original rule: the sidecar is written only when none exists (#698). That write is create-only and runs under the same barrier, so it can never land over a compare-and-swap edit. Merging duplicate assets moves their divergence rows to the surviving asset. When either asset came from a backup, the merge also sets the survivor due again for the `canonical-backup-sidecars` check, since its moved locations may still hold pre-#5021 sidecars.

| GET    | `/api/lens-profiles/:digest` | Retrieve exact original XML by its 64-character lowercase BLAKE3 digest. Missing profiles return `404`.                                                                                                                                      |

The server verifies hashes when storing and reading imported bytes. GridFS retains profiles across process restarts. Render children restore the reference from the XMP through the shared parser before developing; disabled corrections need no profile, and embedded corrections take priority. Importing a profile does not itself acknowledge an approximate match or edit a photo's sidecar.

### SQLite database backups

All `/api/admin/backup/db` routes require an authenticated **owner**.

| Method | Path                          | Result                                                                                                                                             |
| ------ | ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/admin/backup/db`        | `{ policy, status, last_success_at, running }`; credentials are never returned                                                                     |
| PUT    | `/api/admin/backup/db/config` | Save a complete policy: `enabled`, `bucket`, `hour` (0–23 server-local), `daily`, `weekly`, `monthly`, `yearly` (integer 0–1000); returns settings |
| POST   | `/api/admin/backup/db`        | Start an asynchronous snapshot using saved settings; `202 { accepted: true }`, `409` if already running, `400` if R2 is unconfigured               |

Defaults: automatic backups disabled, no backup bucket, hour 3, retention
7/4/12/5. A manual backup works with automatic backups disabled. Poll GET for
completion. `status` contains `state`, `started_at`, and on completion
`finished_at`, `key`, `bytes`, `compressed_bytes`, or `error`. A successful backup
can include `retention_error` when cleanup failed. `running: false` with a stored
`state: running` means the previous process was interrupted. Policy updates
return 409 while a backup runs. Backups use the saved Cloudflare credentials and
the private backup bucket specified in this policy; thumbnail mirroring need not
be enabled. See [disaster recovery](architecture.md#sqlite-offsite-backups-3816)
for credentials provisioning, storage requirements, and the offline restore CLI.
