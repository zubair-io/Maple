# 08 — I/O

RAW formats supported, XMP sidecar strategy, catalog persistence, export, metadata round-trip. This document is where the outside world — filesystems, network shares, the Apple Photos library, exported image files — meets Maple's data model.

The data types involved are in [`01-data-model.md`](./01-data-model.md); the pipeline that consumes them is in [`02-pipeline.md`](./02-pipeline.md); the XMP byte canonical form is in [`xmp-canonical-format.md`](../xmp-canonical-format.md).

## Supported input formats

### RAW (via Rust `raw-core` + `rawler`)

| Format     | Extensions             | Notes                                                    |
| ---------- | ---------------------- | -------------------------------------------------------- |
| Adobe DNG  | `.dng`, `.DNG`         | Primary test format. TIFF-based.                         |
| Canon      | `.cr2`, `.cr3`         | CR2 pre-2018 bodies; CR3 for R-series.                   |
| Nikon      | `.nef`, `.nrw`         | Compressed and uncompressed.                             |
| Sony       | `.arw`, `.sr2`, `.srf` |                                                          |
| Fuji       | `.raf`                 | Bayer and X-Trans; X-Trans demosaic is weak (see below). |
| Olympus    | `.orf`                 |                                                          |
| Panasonic  | `.rw2`                 |                                                          |
| Pentax     | `.pef`, `.ptx`         |                                                          |
| Samsung    | `.srw`                 |                                                          |
| Hasselblad | `.3fr`, `.fff`         |                                                          |
| Kodak      | `.dcr`, `.kdc`         |                                                          |
| Leaf       | `.mos`                 |                                                          |
| Minolta    | `.mrw`                 |                                                          |
| Phase One  | `.iiq`                 |                                                          |

Everything rawler supports, Maple inherits. A format rawler doesn't recognize falls through to the `CIRAWFilter` fallback on Apple (which has its own supported list) or fails on the web.

**X-Trans caveat.** Fuji's non-Bayer CFA requires a different demosaic (Markesteijn or 3×3 VNG). Maple's AMaZE/HA don't apply. In v1, X-Trans on Apple falls back to CIRAWFilter (which does handle it); on the web, X-Trans is not usable in v1. See [`09-open-questions.md`](./09-open-questions.md).

### Standard image formats (pass-through, no demosaic)

| Format | Extensions       | Notes                                                      |
| ------ | ---------------- | ---------------------------------------------------------- |
| JPEG   | `.jpg`, `.jpeg`  | Profile: embedded ICC, assumed sRGB if untagged.           |
| HEIC   | `.heic`, `.heif` | iOS-native. Profile: Display P3 typical.                   |
| PNG    | `.png`           | Profile: sRGB typical.                                     |
| TIFF   | `.tif`, `.tiff`  | Baseline TIFF only; no multi-page, no unusual compression. |
| WebP   | `.webp`          | Web only; Apple reads via ImageIO.                         |

These skip the demosaic stage. Decode produces an RGB buffer in the profile's native colorspace, then the standard adjustment chain applies.

### What's not supported

- Raw video (ProRes RAW, CinemaDNG sequences) — Phase 5.
- Layered formats (PSD, TIFF with layers) — out of scope.
- EXR on input — out of scope for now (scene-referred input path); EXR export is supported (see § Export).

## Sidecar storage strategy

### Location rules

| Source           | Sidecar location                   | Filename convention                                                               |
| ---------------- | ---------------------------------- | --------------------------------------------------------------------------------- |
| **Filesystem**   | Sibling to the image               | `IMG_0001.CR3` → `IMG_0001.xmp` (same stem)                                       |
| **SMB**          | Sibling to the image, on the share | same                                                                              |
| **Apple Photos** | App Support directory              | `~/Library/Application Support/MapleMaple/sidecars/{PHAsset.localIdentifier}.xmp` |

**Filesystem / SMB naming**: `{stem}.xmp` alongside the image. Case of `.xmp` vs `.XMP` matches the image file's extension case on case-sensitive filesystems. On macOS (case-insensitive by default), always lowercase.

**PhotoKit assets**: PhotoKit doesn't expose the file's filesystem path for user-writable sidecars. Maple keeps sidecars in its sandboxed App Support directory, keyed by `PHAsset.localIdentifier`. If a PhotoKit asset is deleted, its sidecar becomes orphaned; a daily sweeper quarantines orphaned sidecars and deletes them after 30 days. Mechanics in § `PhotoKitSource` below.

### Collision handling

- **Existing sibling `.xmp` written by Lightroom**: Maple reads it, preserves all `passthroughFields` and `passthroughNodes`, and writes back. Round-trip is lossless for unknown fields.
- **Existing sibling `.xmp` written by another tool we don't recognize**: same — passthrough handles it.
- **Read-only filesystem**: sidecar write fails. UI surfaces the error inline. No fallback location; we don't want two copies of the sidecar diverging.
- **Sibling `.xmp` with the same stem as a sidecar but for a video or other non-image**: not distinguishable structurally. Maple only writes sidecars adjacent to images it can open.

### Debounce and flush

From [`07-ui-architecture.md`](./07-ui-architecture.md) § The slider interaction loop:

- 500ms debounce on writes after slider changes.
- Synchronous flush on `EditSession.endEditing()`.
- No write on pure zoom/pan/selection changes.

## XMP wire format

See [`xmp-canonical-format.md`](../xmp-canonical-format.md) for the authoritative byte specification. This section describes the _what_ and _why_; that doc describes the _how_.

### Namespaces

| Prefix  | URI                                            | Purpose                                                       |
| ------- | ---------------------------------------------- | ------------------------------------------------------------- |
| `xmp:`  | `http://ns.adobe.com/xap/1.0/`                 | Rating, basic XMP metadata.                                   |
| `crs:`  | `http://ns.adobe.com/camera-raw-settings/1.0/` | Adobe Camera Raw adjustments.                                 |
| `papp:` | `http://ns.justmaple.app/photo/1.0/`           | Maple-specific: flag, color label, (future) masks, snapshots. |

The three above are declared on every `rdf:Description`, in that order, whether or not the payload uses them. The metadata namespaces (`dc:`, `exif:`, `photoshop:`, `Iptc4xmpCore:`, `xmpRights:`) follow, declared only when used. `xmpMM:` was listed here before #1577 but no Maple writer has ever emitted an `xmpMM:` attribute; an imported one rides the passthrough bucket and sorts with the other unknown namespaces.

No parser resolves a namespace URI — all three key on the prefix — so the `papp:` URI is a naming choice, not a compatibility constraint. See `docs/xmp-canonical-format.md` § "The `papp:` namespace URI" for the full reasoning and the #1577 harmonization.

### Field coverage

**Fully mapped to `AdjustmentModel`** (see [`01-data-model.md`](./01-data-model.md) for the tables):

- Every slider: Exposure2012 through ColorNoiseReduction.
- Tone curves: two families, each with master + RGB, nested element form. Scene-linear curves under `papp:SceneLinearToneCurve*`; display-referred (Lightroom-compatible) curves under `crs:ToneCurvePV2012*`. Both families can coexist on the same image and apply at different pipeline stages. See [`03-algorithms.md`](./03-algorithms.md) § Tone curve representation, [`01-data-model.md`](./01-data-model.md) § Tone curves, and [`09-open-questions.md`](./09-open-questions.md) § 9.50.
- Crop fields: top/left/bottom/right + angle + HasCrop + CropConstrainToWarp.
- Process version: Version, ProcessVersion, HasSettings (always emitted).
- **`papp:ViewTransformVersion`** — string, e.g. `"agx-1"`. Identifies the exact AgX coefficient set + LUT used for this edit. Stamped on first save; preserved on subsequent edits unless the user explicitly re-renders with the current version. See [`09-open-questions.md`](./09-open-questions.md) § 9.44.
- **`papp:AgXLook`** — string, one of `"neutral"`, `"punchy"`, `"golden"`. Orthogonal to `ViewTransformVersion`; changing the look does not bump the version tag. Defaults to `"neutral"` if absent.
- **`papp:HighlightRecoveryMode`** — string, one of `"off"` (default), `"blend"`, `"luminance"`. Selects the highlight reconstruction algorithm applied between demosaic and the DCP color matrix. See [`09-open-questions.md`](./09-open-questions.md) § 9.10 and [`03-algorithms.md`](./03-algorithms.md) § 3.3a.

**Partially mapped**:

- `crs:MaskGroupBasedCorrections` — read and preserved in `passthroughNodes`, not interpreted. Masks are Phase 4.
- `crs:Look` — preserved in passthrough.

**Known and explicitly skipped**:

- History entries (`xmpMM:History`) — preserved in passthrough.
- Derived-from links (`xmpMM:DerivedFrom`) — preserved in passthrough.
- Snapshots — preserved in passthrough.

The rule: unknown or unimplemented fields are preserved, never dropped. Round-tripping a Lightroom sidecar through Maple and back to Lightroom must produce no observable change to Lightroom's interpretation.

### Sidecar import discrimination (tone curves)

`crs:ToneCurvePV2012*` always means **display-referred** in Maple's XMP — but historically Lightroom-readable sidecars from any source use the same key, and Maple needs to know whether to apply the curve at stage 12a (display-referred slot) or treat it as passthrough. The discrimination is purely a check on which writer marker is present:

- Sidecar carries any `papp:` markers (`papp:ViewTransformVersion`, `papp:AgXLook`, `papp:HighlightRecoveryMode`, or any `papp:SceneLinearToneCurve*`) → Maple-written. `crs:ToneCurvePV2012*` was emitted for Lightroom round-trip; load into stage 12a.
- Sidecar carries `crs:Version` / `crs:ProcessVersion` but no `papp:` markers → Lightroom-written or written by a Lightroom-compatible third-party tool. `crs:ToneCurvePV2012*` is display-referred; load into stage 12a.
- Neither marker set present → assume display-referred (safer default; matches XMP convention for the field).

In all three cases the curve is loaded into the display-referred slot. The discrimination above only documents the writer; it does not change the field's semantics. Maple's own scene-linear curves never write to `crs:ToneCurvePV2012*`; they write to `papp:SceneLinearToneCurve*`. See [`09-open-questions.md`](./09-open-questions.md) § 9.50.

## Source adapters

### `FilesystemSource`

Backed by POSIX `opendir` + security-scoped bookmarks (Apple) or the File System Access API (web, Chromium only, v2). Treats the user's selected folder as the root; enumerates recursively on demand.

- **Enumeration**: breadth-first; yields `ImageAsset` stubs as files are visited. Filters by extension allowlist (see supported formats).
- **Security-scoped bookmarks** (Apple): each user-selected folder gets a persistent bookmark stored via `BookmarkStore`. On app launch, bookmarks are resolved; access is re-granted via `startAccessingSecurityScopedResource()`. `findScopedParent(for:)` walks ancestor URLs to find the closest scoped root for any child.
- **Last-folder restore**: `await filesystemSource.ensureReady()` blocks until scoped URLs are populated. Prevents EPERM on cold start.
- **Folder change detection**: on Apple, `DispatchSource.makeFileSystemObjectSource` on each visible folder; on web, manual refresh only.

### `SMBSource`

Backed by AMSMB2, an Apple-framework SMB client.

- **Connection**: Keychain-stored credentials (host, share, username, password). Test connection on add; surface failures inline.
- **Enumeration**: same interface as `FilesystemSource`; backed by `SMBFileHandle.listDirectory`.
- **Read**: fetch the whole file to local cache (see `SMBFileData` cache in [`05-performance.md`](./05-performance.md)). Avoid partial reads — RAW decoders can't stream, and re-fetching on every slider change would be unusable.
- **Write** (sidecars): written directly to the share via AMSMB2's `writeFile`. No debounce interaction with network weather; the 500ms debounce is still effective.
- **Disconnect**: connection object is persistent across app sessions; reconnects on first access of a given host.

### `PhotoKitSource`

Backed by PhotoKit (`PHFetchResult<PHAsset>`, `PHImageManager`).

- **Enumeration**: fetches one collection at a time (all photos, favorites, individual albums).
- **Read**: `PHImageManager.requestImageDataAndOrientation` for the RAW bytes; synthesizes a data URL for the decoder.
- **Write**: sidecars write to `~/Library/Application Support/MapleMaple/sidecars/{identifier}.xmp`, not to any PhotoKit attachment. PhotoKit's "adjustments" API is technically the right place, but its use requires modifying the asset via `PHPhotoLibrary.shared().performChanges`, which is heavy and fragile. Maple's sidecars-on-the-side approach is simpler; the trade-off is that Maple's edits aren't visible in other apps that respect PhotoKit adjustments.
- **Deletion sweep**: a two-phase quarantine sweeper, runs at most once per 24h on app launch (debounced via a `UserDefaults` timestamp). Gated on `PHPhotoLibrary.authorizationStatus(for: .readWrite) == .authorized`; runs are skipped silently for `.limited`, `.notDetermined`, `.denied`, and `.restricted` because `fetchAssets(withLocalIdentifiers:)` cannot distinguish "asset deleted" from "asset outside the limited subset" or "library not yet loaded." Phase 1: enumerate `~/Library/Application Support/MapleMaple/sidecars/*.xmp`, batch-fetch identifiers (500 at a time) via `PHAsset.fetchAssets(withLocalIdentifiers:)`, and `mv` each unresolved sidecar to `~/Library/Application Support/MapleMaple/sidecars/.orphaned/{YYYY-MM-DD}-{identifier}.xmp`. Phase 2: same run, delete anything in `.orphaned/` whose date prefix is ≥30 days old. The directory listing is the only state — no parallel state file. Sweep is silent in v1; if a user reports lost edits, the recovery path is "look in `.orphaned/`."

## Library index (non-authoritative cache)

Described briefly in [`01-data-model.md`](./01-data-model.md); elaborated here.

### Why it exists

Cold folder open of a 5000-image directory with sidecars would require parsing 5000 XMP files to populate culling state. That's 5–30 seconds of CPU-bound work. The index caches the parsed state in a single JSON blob keyed by file metadata.

### Location

| Source     | Path                                                                        |
| ---------- | --------------------------------------------------------------------------- |
| Filesystem | `{folder}/.maple/index.json`                                                |
| SMB        | same, on the share                                                          |
| PhotoKit   | `~/Library/Application Support/MapleMaple/photokit-index.json` (one global) |

`.maple/` is a hidden sibling directory. Gitignored by convention (users don't commit this); also ignored by Dropbox, iCloud, etc. via their ignore mechanisms where available.

### Schema

```json
{
  "version": 1,
  "lastFullScan": "2026-04-22T10:00:00Z",
  "assets": [
    {
      "filename": "IMG_0001.CR3",
      "fileSize": 42532100,
      "modificationDate": "2026-04-10T14:32:11Z",
      "pixelWidth": 6720,
      "pixelHeight": 4480,
      "isRAW": true,
      "cullingState": {
        "rating": 4,
        "flag": "pick",
        "colorLabel": "green"
      },
      "thumbnailHash": "a5f..."
    }
  ]
}
```

### Invalidation

- **File size or mtime mismatch**: refresh entry from disk + sidecar.
- **Sidecar written more recently than index entry**: refresh.
- **Index schema version mismatch**: blow it away and rebuild.

Maple is always allowed to ignore the index. A corrupt index is not a fatal error.

### Concurrent write protection

A single writer lock (POSIX flock on the `.maple/index.json` itself). Concurrent writers (two Maple instances on different machines syncing via a network share) are expected to be rare and are handled by last-writer-wins; the overhead of stronger consistency isn't justified.

## Server-side persistence (Phase 5, design phase)

See [`maple-maple-server-spec.md`](../maple-maple-server-spec.md) for the full spec; this section is a summary of the contract v1 needs to respect even without a working server.

### Role

The server is a **sidecar sync engine + thumbnail cache**. It does not render. It does not replace the authoritative sidecar files.

### Collections (MongoDB)

| Collection       | Shape                                                                                                                     |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `users`          | `{ _id, email, passkeys: [...], createdAt }`                                                                              |
| `credentials`    | WebAuthn credential records                                                                                               |
| `libraries`      | `{ _id, userId, name, createdAt }`                                                                                        |
| `source_folders` | `{ _id, libraryId, path, hostAlias }`                                                                                     |
| `assets`         | `{ _id, libraryId, folderId, filename, fileSize, mtime, sidecarMtime, cullingState, thumbnailUrl, width, height, isRAW }` |
| `jobs`           | Background work: thumbnail generation, sidecar sync, index rebuild                                                        |

### Endpoints (design, not fully implemented)

- `POST /library` — create a library under the authenticated user.
- `POST /library/:id/sync` — a client uploads a folder's `.maple/index.json` + a delta of changed `.xmp` files; the server merges into `assets`.
- `GET /library/:id/assets` — fetch paginated asset records for the browse view.
- `GET /thumbnail/:assetId` — fetch a cached thumbnail.
- `POST /asset/:id/sidecar` — write a sidecar (triggers re-index).

### Authentication

WebAuthn / passkeys. No passwords. First-run: user registers a passkey; subsequent access is frictionless on trusted devices.

### Not-v1 surface

- Real-time sync (WebSocket push). v1 is pull-based.
- Collaboration / shared libraries. v2.
- Server-side render. Never.

## Export

### Formats (from [`02-pipeline.md`](./02-pipeline.md) § Trace C)

The export matrix splits into two classes — **display-referred** formats (the view transform is baked in) and **scene-linear** formats (the view transform is skipped and the raw scene-linear values are written). See [`04-color-management.md`](./04-color-management.md) § Export for the full rationale.

| Format         | Referred | Color space         | Bit depth                     | View transform  | Use case                                                  |
| -------------- | -------- | ------------------- | ----------------------------- | --------------- | --------------------------------------------------------- |
| JPEG           | Display  | sRGB or Display P3  | 8                             | AgX applied     | Web sharing, email, general-purpose                       |
| HEIC           | Display  | Display P3          | 10                            | AgX applied     | iOS-native, efficient wide-gamut                          |
| PNG            | Display  | sRGB or Display P3  | 8 / 16                        | AgX applied     | Lossless web, screenshots                                 |
| TIFF (display) | Display  | Display P3 or sRGB  | 16                            | AgX applied     | Print workflow, further editing in display-referred tools |
| TIFF (scene)   | Scene    | Linear Rec.2020 D65 | 16 (half-float) or 32 (float) | **Not applied** | Scene-linear handoff to another scene-referred editor     |
| EXR            | Scene    | Linear Rec.2020 D65 | 16 (half-float) or 32 (float) | **Not applied** | VFX / compositing handoff; preserves full dynamic range   |

**Why two TIFF modes.** A 16-bit display-referred TIFF in Display P3 is the traditional "send to Photoshop" format. A 16-bit scene-linear TIFF in Rec.2020 preserves highlight headroom and the scene-referred state, for workflows that apply their own view transform downstream. The two are not interchangeable — they are different images of the same scene state.

**EXR encoder.** Unified on the Rust `exr` crate, compiled for both Apple FFI and WASM (single source of truth, automatic numerical parity across platforms). Defaults: `half` (f16) channels; PIZ compression (lossless, wavelet, optimised for photographic content); Rec.2020 + D65 chromaticities header; `displayWindow` and `dataWindow` identical and equal to image bounds; channel layout `R, G, B`. Alternates exposed in the export dialog: `float` (f32) for precision-critical handoff; ZIP for synthetic / smooth-gradient content. No lossy options (B44, DWAA) — anyone reaching for EXR wants full precision. A Blender round-trip CI gate validates encoder correctness; see [`11-testing.md`](./11-testing.md).

### Export configuration

```
ExportConfiguration {
    format: .jpeg | .heic | .png
                | .tiffDisplay | .tiffScene        // scene-linear variant is Rec.2020
                | .exr                              // half/float, PIZ default
    quality: Int                  // 1..100, JPEG/HEIC only
    colorSpace: .sRGB | .displayP3 | .linearRec2020
                                                    // sRGB/P3 valid for display-referred only;
                                                    // linearRec2020 valid for scene-linear TIFF / EXR
    bitDepth: .int8 | .int16 | .float16 | .float32
                                                    // scene-linear formats: float16 or float32 only
    longEdge: Int?                // nil = original size
    stripMetadata: Bool           // see below
    fileNameTemplate: String      // e.g., "{filename}-edited"
    outputFolder: URL
}
```

The UI constrains invalid combinations: selecting a scene-linear format collapses `colorSpace` to `linearRec2020` and restricts `bitDepth` to float variants. Selecting a display-referred format hides the `float*` choices.

### Pipeline

1. Load sidecar → `AdjustmentModel`.
2. Decode RAW at full resolution (Rust core, export-quality demosaic if compiled with `high-quality-demosaic`).
3. Apply the **scene-linear chain** (stages 1–11 from [`02-pipeline.md`](./02-pipeline.md)) at full resolution in Linear Rec.2020 D65, f32 throughout, tiling if > 50MP.
4. **Branch on format class:**
   - **Display-referred formats** (JPEG, HEIC, PNG, TIFF display): apply the AgX view transform (stage 12), then the display encode (stages 13–14): Rec.2020 → target gamut (sRGB or Display P3), then the format's transfer function (sRGB EOTF, or `pq` for HEIC10 if configured).
   - **Scene-linear formats** (TIFF scene, EXR): **skip** stages 12–14. Write linear Rec.2020 D65 values directly. No gamut clamp, no tone mapping — negatives and values > 1.0 pass through as-is.
5. Resize to `longEdge` if set. For scene-linear output, resize is applied in scene-linear space (box-filtered, preserving radiometry); for display-referred output, resize happens after AgX but before the gamut/transfer encode, to avoid ringing around clipped highlights.
6. Quantize and encode:
   - Display-referred: `CGImageDestination` (Apple) or canvas `toBlob` (web) at the target bit depth.
   - Scene-linear TIFF: `CGImageDestination` with `kCGImagePropertyTIFFCompression = LZW` and an fp16/fp32 sample format. Embedded profile: **Linear Rec.2020 D65** (a synthesized ICC, not sRGB).
   - EXR: Rust `exr` crate (same binary on Apple via FFI, web via WASM) with `half` (default) or `float` channels; PIZ compression default, ZIP alternate; chromaticities header set to Rec.2020 primaries + D65; `displayWindow` and `dataWindow` identical and equal to image bounds; channels in `R, G, B` order.
7. Copy metadata per `stripMetadata` flag.
8. Write to `outputFolder`.

**What changes vs a traditional display-referred exporter.** The export pipeline used to end at "encode to sRGB/Display P3"; now it explicitly either applies AgX (display-referred outputs) or bypasses it (scene-linear outputs). The `viewTransformVersion` tag (see [`04-color-management.md`](./04-color-management.md) § View transform versioning) is embedded in the XMP sidecar copied to the export for display-referred formats, so a re-import reproduces the same rendering.

### Metadata handling

`stripMetadata` has three effective modes in v1:

- **false (default)**: all EXIF, IPTC, XMP, and color profile are copied through.
- **true (partial impl)**: the profile is stripped (bad default), plus EXIF GPS, plus camera serial. Most other EXIF is preserved.

The "selective strip" UI (strip GPS but keep camera info, strip serial but keep creation date, etc.) is a Phase 5 item. See [`09-open-questions.md`](./09-open-questions.md) § Selective metadata strip.

### iOS share sheet

Not implemented in v1. iOS export currently writes to the device's Photos library via PhotoKit, or to the app's Documents folder. A share-sheet presenter is Phase 5.

### Batch export

Not supported in v1. Users export one image at a time. Batch is a Phase 4 item (the underlying pipeline is ready; the UI and progress reporting aren't).

## Import rules

Maple deliberately does not copy, relocate, or modify images on import. A "source" is a reference to a location, not a copy of its contents.

- **Filesystem**: the user's folder is the source. Images stay where they are.
- **SMB**: images stay on the share. Maple caches them locally for read performance; the cache is disposable.
- **PhotoKit**: PhotoKit owns the files. Maple reads via `PHImageManager`.

Consequences:

- Moving a file in Finder breaks its sidecar association. Maple re-associates if the user adds the new location as a source and the sidecar follows the file (which it will, if moved as a pair).
- Renaming an image orphans its sidecar. No auto-rename of sidecars in v1.
- Deleting an image outside Maple leaves the sidecar. Maple's periodic sweeper cleans up orphans.

## Thumbnail generation

Thumbnails are generated on-demand during grid browsing and cached. Three-layer cache described in [`05-performance.md`](./05-performance.md) § Five caches.

### Source preference

1. **Embedded JPEG in RAW**: extracted via `CGImageSource` (Apple) or TIFF tag parsing (Rust, on web). Fastest. Typical ~1600×1200, good enough for grid.
2. **Decode first N×N pixels of the full image**: slower but handles formats with no embedded preview or where the preview is too small.
3. **Full decode then downsample**: rare; only for formats with no embedded preview and whose structure doesn't permit partial decode.

### Format on disk

JPEG, sRGB, quality 80, max 500×500 (contain-fit). Naming: `{sha256(path + mtime)}.jpg` under `.maple/thumbs/`.

### Refresh on edit

After an edit session ends and a rendered preview is cached, a fresh thumbnail is generated from the rendered preview (downsampled). This ensures the grid shows the edited result, not the unedited embedded JPEG. See [`02-pipeline.md`](./02-pipeline.md) § B.7.

The rendered-preview cache is post-AgX, post-display-encode (it is the bytes that were on screen), so the downsampled thumbnail is already display-referred sRGB. The thumbnail cache key includes `viewTransformVersion` (see [`05-performance.md`](./05-performance.md) § RenderedPreviewCache) so a future view-transform update invalidates stale thumbnails along with the rendered previews that produced them.

## Concurrency and sidecar writes

Several clients could theoretically write to the same sidecar (one user on Mac, same user on iPad, both opening an SMB share). v1's strategy:

- **Last writer wins.** No locking. The XMP format has no conflict-resolution facility.
- **mtime monitoring**: Maple watches sidecars for external modification; if the sidecar changes on disk while a session is open, the user is offered "Keep my changes" / "Reload from disk".
- **Version signaling**: `crs:Version = "11.0"` and Maple's `papp:*` fields make it obvious which writer produced the file. Not a conflict-resolution mechanism; a debugging aid.

Collaboration — proper merge of concurrent edits — is out of scope. See [`00-overview.md`](./00-overview.md) § Non-goals.

## Testing I/O

- **Unit tests** for the XMP parser and serializer on both Swift and TS. Golden-file corpus in `test-fixtures/sidecars/`. See [`06-cross-platform.md`](./06-cross-platform.md) § Sidecar parity.
- **Integration tests** for the file system source: create a temp directory, write images + sidecars, enumerate, verify culling state.
- **SMB integration tests** run against a Dockerized Samba server (see `docker-compose.yml`); CI-only.
- **PhotoKit integration tests** run only on-device or simulator; no CI today. See [`09-open-questions.md`](./09-open-questions.md) § PhotoKit CI.
- **Round-trip export tests**: export a known RAW → re-decode the exported JPEG → compare pixels against a golden reference with ΔE budget. Two variants: (1) display-referred path (JPEG / HEIC / PNG / TIFF-display), ΔE budget ≤ 5 vs. the Apple reference render; (2) scene-linear path (TIFF-scene / EXR), per-pixel relative error ≤ 1e-3 vs. the pre-AgX tap in the pipeline — this proves the exporter is bypassing stages 12–14 cleanly.
