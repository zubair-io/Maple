# Plan: #1033 — on-GPU dehaze airlight reduction (epic #925 P4b C5b)

## Goal
Replace the per-tick GPU→CPU readback in the dehaze-active live path (`render_dehaze_split`
+ `encode_chain_f32_dehaze_split` in `live_session.rs`) with an **on-GPU reduction** that
computes the atmospheric-light A without leaving the device. Default the live dehaze path
to the on-GPU reduction; keep the CPU-readback path available as a fallback.

## What `compute_airlight` does (the thing to replicate on-GPU)
`raw-gpu/src/dehaze.rs::compute_airlight`:
1. dark channel `dc[i]` = 15×15 clamp-to-edge window min of min(r,g,b)  (ALREADY a GPU kernel:
   `dehaze_min.wgsl` mode 0 → the `dc` scalar plane in `DehazePass::encode`).
2. `top_n = max(n/1000, 1)` (128×128 → 16).
3. sort indices descending by `dc`, take the top_n, average the ORIGINAL rgb at those
   positions → A = [Σr/k, Σg/k, Σb/k]. (NOT a max — a top-0.1% AVERAGE.)

## On-GPU reduction design: histogram → percentile threshold → masked average
The brightest top_n dark-channel positions ≈ the dark-channel values ABOVE a percentile
threshold τ where (#dc ≥ τ) ≈ top_n. Then A = mean of orig.rgb over {i : dc[i] ≥ τ}.

Sort tie-break can't match on-GPU (stated in ticket) — gate is a TOLERANCE, not bit-exact.

### Passes (all ≤4 storage; pooled scratch; zero-alloc on re-render)
Inputs available at reduction time: `orig` (RGBA, ping-pong src) + `dc` (scalar plane,
already computed by the dehaze min kernel).

1. **histogram** (`airlight_hist.wgsl`): atomic histogram of `dc` over [0,1] into `BINS`
   bins. dc is min(r,g,b) of scene-linear values; clamp to [0,1] for binning (values >1
   are rare in dark channel and land in the top bin — correct, they're the brightest).
   - storage: dc (read) + histogram (atomic read_write u32). 2 storage. OK.
   - workgroup-local atomic histogram → merge to global (or direct global atomics; BINS
     small, contention acceptable at 128px; revisit if slow). Use global atomics for
     simplicity + correctness first.
2. **threshold + masked sum** — two sub-steps to find τ then sum. Options:
   - (a) one small single-workgroup pass reads the histogram, scans bins from the top
     accumulating counts until ≥ top_n → emits the threshold BIN index into a tiny buffer.
   - (b) masked sum: each pixel with dc ≥ τ adds orig.rgb + 1 to atomic accumulators
     (sum_r, sum_g, sum_b, count). Atomics are u32 → use fixed-point (scale floats by a
     large factor and atomicAdd integers) OR atomic compare-exchange float emulation.
     SIMPLER + DETERMINISTIC: fixed-point. Multiply rgb by SCALE (e.g. 2^20) and round,
     atomicAdd u32 (with overflow headroom: max sum = 16384px * (~5.0 HDR) * 2^20 ≈ 8.6e13
     > u32). NEEDS u64 atomics (not in downlevel) OR partial sums.
   - **Chosen: workgroup-reduction masked average, NO atomics for the sum.** Single
     workgroup (64 threads) strided over all pixels: each thread accumulates a partial
     (sum_rgb, count) in registers over its stride, then a workgroup-shared tree-reduce →
     thread 0 writes A = sum/count to the airlight buffer. Exact f32 partial sums, no
     atomics, deterministic. Count threshold τ comes from the histogram pass.
   - This collapses threshold-scan + masked-average into ONE single-workgroup pass that
     reads (histogram OR dc) + dc + orig and writes airlight. Storage check:
     dc + orig + airlight_out = 3 storage (+ histogram uniform-ish? histogram is read as
     storage = 4). OK if ≤4.

### Threshold semantics — match top_n average as closely as possible
`compute_airlight` averages EXACTLY top_n pixels. A histogram threshold averages all pixels
in bins ≥ τ_bin, whose count ≈ top_n but not exact (bin granularity + ties at the boundary
bin). With enough bins (e.g. 1024–4096) the boundary bin holds few pixels → count ≈ top_n
and A ≈ within tolerance. Document the tolerance from the realistic fixture.

Alternative to nail it tighter: pick τ_bin such that count(≥τ_bin) is the SMALLEST count
≥ top_n (i.e. include the boundary bin). This averages a few EXTRA pixels (those tied in
the boundary bin) but they're all near the same dc value as the true cutoff, so their orig
rgb is similar → small A delta. This is the deterministic, defensible choice.

## Threading airlight (GPU value) into transmission + recover WITHOUT a 5th storage
- `dehaze_recover.wgsl` already uses 4 storage (orig+ab+sky+out). CANNOT add a storage binding.
- KEY FACT: uniforms do NOT count against `max_storage_buffers_per_shader_stage` (4); the
  uniform cap is 12 (downlevel_defaults). wgpu-types 23 confirmed.
- So: compute airlight into a small STORAGE buffer (4 f32), then GPU→GPU
  `copy_buffer_to_buffer` it into a dedicated AIRLIGHT UNIFORM buffer (UNIFORM|COPY_DST).
  Transmission (`dehaze_min` mode 1) and recover read airlight from this 2nd uniform binding.
  No CPU readback anywhere.
- Storage budget after change:
  - dehaze_min mode 1: input + output = 2 storage + 2 uniforms (params + airlight). OK.
  - dehaze_recover: orig+ab+sky+out = 4 storage + 2 uniforms (params + airlight). OK.

## DehazePass: two airlight sources
- Keep `airlight: [f32;3]` CPU path (headless dehaze/*.tests use `DehazePass::new`).
- Add a GPU-buffer source so the live session can supply an on-GPU-reduced airlight buffer.
- In `encode`: write the airlight uniform from EITHER source:
  - CPU: `queue.write_buffer(airlight_uniform, a4_bytes)`.
  - GPU: `encoder.copy_buffer_to_buffer(reduction_out, 0, airlight_uniform, 0, 16)`.
- The airlight uniform is bound to both transmission + recover (pass it as an extra buffer
  arg to `encode_simple`; declare `var<uniform>` at the new binding in the WGSL).
- REMOVE the `airlight` field from `MinParams` (mode1) + `RecoverParams`; read from the new
  uniform binding instead. (Mode 0 dark-channel ignores airlight — fine.)

## Live session wiring
- `render_dehaze_split` / `encode_chain_f32_dehaze_split`: instead of prefix → readback →
  CPU compute_airlight → suffix, run: prefix → on-GPU reduction (over post-prefix buffer +
  its dc) → suffix that consumes the GPU airlight buffer — ALL in encoders with NO map.
  - The reduction needs the post-prefix buffer's `dc`. The dehaze pass computes `dc` itself.
    Cleanest: have the reduction run as part of the DehazePass encode (it already computes dc).
    So the DehazePass, when GPU-sourced, computes dc → reduction → airlight uniform → rest.
  - This means: NO split needed for the airlight! The DehazePass can compute its own airlight
    on-GPU from its `src` (the post-prefix buffer it receives). The whole reason for the split
    was the readback; with on-GPU reduction the dehaze pass is self-contained → the live chain
    runs in ONE submit even with dehaze active (a perf win beyond removing the readback).
  - KEEP build_live_split + the CPU fallback path for safety/tests, but the live session
    DEFAULTS to the single-submit on-GPU-airlight path.
