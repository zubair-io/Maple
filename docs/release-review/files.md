## Why F1 to F3 hold up

- The primary is copied to a private sibling, byte-compared, then published without replacing any occupant (`src/api/src/fs/relocate-publish.ts`); the original is deleted only after the caller's identity repoint succeeds (`relocate.ts`, `relocate-originals.ts`). A failure before that point reverts only inodes this move created.
- Trash GC (`src/api/src/workers/trash-gc.ts`) unlinks only paths that resolve inside `<library>/.maple/trash/`, refuses `.mapleignore` folders, keeps rows when the library is unreachable, and keeps a surviving copy of a multi-location photo.
- Restore (`src/api/src/library/restore-source.ts`, `src/api/src/fs/trash.ts`) is jailed to the trash directory, never replaces an occupant (a `.restored[.N]` suffix is used), and refuses a destination inside `.maple/`.
- SMB restore (`SMBFileOperations+Restore.swift`) copies and hash-verifies into private staging, publishes with exclusive rename, and rolls back only its own verified copies.
